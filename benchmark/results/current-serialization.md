## Reading the numbers

On every flat dataset above, plain `csv_rfc4180` has the lowest token count
of all five encoders — lower than both `toon_official` and `vigesimal_typed`.
That is the real tradeoff: CSV is smallest, but it only checks textual cells,
not typed JSON round-trips (no booleans, null, or numeric fidelity) — see
Limitations. Pick CSV when the data is already flat text and you don't need
types back; pick a typed format when you do.

`vigesimal_typed`'s median encode time is consistently higher than
`toon_official` on these inputs — roughly 5x-33x slower, worst on
`github_repos` (8.1ms vs 0.24ms). Undiagnosed; likely worth a profiling pass
on the dictionary payoff-gating logic. Both are far below request latency at
this payload size, so this has not been treated as a release blocker.

## Limitations

- Synthetic datasets
- No model quality, API billing, or end-to-end latency measured
- o200k_base counts are not Claude token counts
- CSV checks textual cells, not typed JSON round-trips
- Nested inputs excluded from Vigesimal and CSV comparisons
- Single-machine encoding timings are descriptive only

Exact dependency versions and content hashes are in [the manifest](current-serialization.json).
